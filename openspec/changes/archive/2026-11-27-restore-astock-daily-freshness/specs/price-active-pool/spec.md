# Spec Delta

## Purpose

补一条观测缺口：零产出（一次 flush 都没上报）今天只能读成「0」，读不出「卡在哪一步」。
把逐项进度纳入 pool 的可观测面，使「预热是否真的在推进」成为可判事实。

## MODIFIED Requirements

### Requirement: 池与频次统计可观测

系统 SHALL 暴露池的当前成员（含来源与最近请求时间）与预热结果（成功/失败标的、补入行数），供运维判断"预热是否覆盖了真实用量"。

预热 SHALL additionally 暴露**进行中的进度**，而不只是终态统计：正在处理的标的、已完成数与
计划数 SHALL 在预热运行期间就可见（不要求预热结束后才可读），使「零产出」可以被区分为
「还没开始处理任何标的」与「处理了但每项都失败」两种不同事实。

#### Scenario: 池成员可列出
- **WHEN** 查询池状态
- **THEN** 返回每个成员的标的、来源（配置/频次）、最近请求时间、当前缓存覆盖范围

#### Scenario: 预热报告可查
- **WHEN** 一次预热完成后查询报告
- **THEN** 报告含每个标的的结果（成功/失败原因）与补入行数

#### Scenario: 进行中的进度可读
- **WHEN** 一次预热正在运行、尚未产出任何写入行
- **THEN** 可以读到当前正在处理的标的与已完成/计划计数
- **AND THEN** 「已完成 0 且已在处理第一个标的」与「一项都没开始」在读数上可区分

#### Scenario: 零产出的两个成因不混同
- **WHEN** 一次预热终态为零产出
- **THEN** 报告能指出它是「未开始即结束」还是「逐项失败」
- **AND THEN** 两种情形各自的失败原因可读
